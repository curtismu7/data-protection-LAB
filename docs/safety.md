# Safety

- Loopback bind only (`DPLAB_BIND` is the explicit opt-in the container uses); the compose file publishes `127.0.0.1` only (a test pins it). The container runs as a non-root user, read-only, with every capability dropped.
- Host header must be a loopback name; writes must be same-origin.
- Netguard blocks every outbound connection (fetch, socket, DNS, UDP) with a self-test, and a test asserts zero attempts in the server process across the whole API in both modes. The regex child process is a separate realm that the parent's guard does not cover, so it installs its own netguard before it handles a job (a doctor check and a test run its self-test and assert six blocked routes and no real attempt). It is started with an empty environment (only the IPC descriptor and a macOS locale marker are present) and a capped heap.
- **The server cannot open a record.** It seals with a fresh ephemeral X25519 key per record (built with `createPrivateKey` from a PKCS8 prefix plus 32 random bytes, then wiped), HKDF-SHA256 and AES-256-GCM, and keeps only ciphertext and clear metadata. There is no decrypt code in `server/src` (a test greps for it), a JWK carrying `d` is refused as a PublicKey, a public key must be a canonical, usable X25519 point (top bit clear, a throwaway key agreement must give a non-zero secret: low-order points are refused at config time), and tests assert the test private key is in no response and no workspace state. The private key is made in the browser with WebCrypto, held in the page's memory only, never sent, never put in localStorage and never logged; decryption happens in the browser when you open one record. A wrong key, or any altered byte, fails the AES-GCM check. The doctor script proves a real seal-then-open round trip with a throwaway key.
- **Nothing the visitor types is echoed.** A value any built-in detector (every personal-data kind, every secret detector) or any of the visitor's own rules recognises is masked in every response field, hop pane, event, error and label: the engine returns offsets, lengths, rule ids and a masked display copy, never a value. The display copy masks EVERYTHING any detector found, whatever the policy scores: a PIIKinds list that narrows what is scored does not un-mask a value. The finders read a normalised copy (zero-width characters, whitespace tricks and fullwidth forms do not hide a value) and the redaction maps back to the original characters. Ids a visitor chooses (rule id, KeyID, scope key, override ids) are refused if they look like personal data or a secret, key names are never quoted in errors, and a value split across stream frames is masked in the earlier frames' displayed copies. A test types a value of every kind, every secret detector and a pasted-rule match through every endpoint, including the error paths and every PIIKinds narrowing, and asserts the raw value is absent from every field and from the console output. Limits: a value no detector recognises (for example nine bare digits, or a custom-rule match that is not in your rules) cannot be masked. Only the labelled scripted mock credential (`sk-MOCK-...`) is shown, in the story only (rule 4). Detector samples are credential-shaped, so they are built on the server at run time and only two booleans per detector leave it.
- **Pasted regular expressions are user-fed.** The TOML parser is bounded (65536 characters, 50 rules, 2000 lines, 2000 characters a string, no recursion; its fields are null-prototype objects, so `__proto__`, `constructor` and `prototype` are ordinary keys that are refused). Each regex is checked statically (no nested quantifiers, quantified alternation, backreferences, lookaround, named groups, repeat counts over 100, more than 6 variable quantifiers (`?`, `*`, `+`, `{n,m}`), more than 400 characters) and then only ever compiled and run in a CHILD PROCESS, never in the server process and never in a thread. A thread cannot be trusted here: `Worker.terminate()` cannot interrupt a regex stuck inside the engine, and the thread kept burning a core after the request returned (reproduced by the reviewer with `a?`x60 + `a`x60). The parent SIGKILLs the child when a job runs over its limit (2 seconds a rule, 4 seconds an inspection, 20000 character input cap) and starts a fresh one. The child cannot be trusted to notice its own parent dying while it is stuck in the engine (a mutation run of this lab left four such orphans spinning at 50% CPU), so it runs a watchdog THREAD (its own isolate, unaffected by the stuck main thread) that SIGKILLs the child if the parent pid changes or a job outlives its deadline plus a 1.5 s grace; the parent also SIGKILLs every child on process exit, SIGTERM, SIGINT and SIGHUP, and on a workspace Reset (queued jobs are dropped and the child running that workspace's job is killed). Tests prove that an uninterruptible pattern is killed, that the pid is really gone, that no child remains after the runner closes, that a parent that dies with SIGKILL leaves no orphan, that a job past its deadline is ended by the child itself, that Reset cancels in-flight work, and that no `regexChild.js` process of this repo remains after the server exits on SIGTERM or SIGKILL. The child has an empty environment and a capped heap and installs its own netguard. Each workspace has its own queue (one running job, three queued, round-robin on a small pool), so a slow rule does not hold up another workspace; a rule that times out is quarantined and reported, and a pasted import is serialised per workspace so concurrent pastes cannot bypass the duplicate-id check or the 50-rule cap. No `eval`, `Function` or `vm` anywhere (a test greps).
- One bad rule refuses the whole paste: nothing is added and Errors names each refused rule; refusals never echo the pattern.
- The server writes no file (a test greps for write calls). The one home-directory touch is reading the optional shared settings file (`~/Development/.env`, or `STANDALONE_ENV`) with `util.parseEnv`, taking only `DPL_LAB_MODE`: no other key enters the server's environment. A bare `MODE` in it is ignored.
- Input is bounded: bodies 32 KB (400 KB for an evaluation, a stream or a rule paste), a text at most 20000 characters, a stream at most 20 frames of 2000, a record at most `MaxBytes` (65536), workspaces, events (200), records (100) and rules (50) capped, and every value used as an object key is type-checked (`Object.hasOwn`).
- Only `.example` and `.invalid` hosts appear in any shipped text (a doctor check scans the filled story in every vertical). The synthetic personal data in the stories is generated from each kind's checksum at run time and belongs to no one.
- Every product claim is labelled "Ping release claim, UNVERIFIED on our tenant" in the banner of every tab, in presenter mode too. Field names from the console swagger of 2026-10-31 are schema only; the lab says so wherever they appear, and tags each field as a swagger name, a lab reading or lab-invented.
